# Sparehour

A calm, time-aware personal planner (product formerly worked on as "Personal Work Management"). Core promise: a Today that knows your real free time, and a guilt-free planning loop.

## Before building anything
- Read `docs/DECISIONS.md`. It is the source of truth for product decisions and lists the open ones — don't silently decide an open question in code; ask.
- Check a feature's milestone tag in `docs/FEATURES.md`. Build only what the current milestone needs; park the rest.
- Data/sync layer: **PowerSync + Supabase**, confirmed by the P0 spike (`docs/engineering/SYSTEM_DESIGN.md` Appendix A′, 2026-09-14; A4 iOS PWA storage still pending a real iPhone). Local stack: `npm run dev:stack` (Supabase on 54321/54322, PowerSync on 8080, writes `.env.local`), then `npm run dev`; sign in as `dev@sparehour.local` / `sparehour`. `@powersync/*` is imported only under `src/data/powersync/` (ESLint enforces it); `src/core/**` stays free of React, data and server imports.
- Sync streams can only match subscription parameters with `=` / `IN` — windowed streams are keyed by month (`months: ['2026-09', …]`), never by a date range.
- Sign-in (DECISIONS.md Q25): an emailed six-digit code or link (`signInWithOtp`; the local template `supabase/templates/magic_link.html` carries both, Mailpit at http://127.0.0.1:54324 catches it) and Google, identity only. `/auth/callback` exchanges a PKCE code or verifies a token hash and sets the cookie. The Google button appears only when the auth server reports the provider enabled: create a Web OAuth client with redirect URI `http://127.0.0.1:54321/auth/v1/callback`, export `SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID` / `_SECRET`, set `enabled = true` under `[auth.external.google]` in `supabase/config.toml`, restart the stack. The password form stays for the dev account and the e2e suite.
- Sync auth: the browser never shows PowerSync its Supabase session. `GET /api/sync/token` mints a five-minute HS256 token with `POWERSYNC_JWT_SECRET`; the service verifies it with the same secret (`PS_SYNC_JWT_K`, base64url, defaulted to the local dev value in `powersync/docker-compose.yml`). `dev-stack.sh` writes the local secret into `.env.local`.
- The browser reaches PowerSync through its own origin: `NEXT_PUBLIC_POWERSYNC_URL=/powersync` and a rewrite in `next.config.ts` to `POWERSYNC_INTERNAL_URL` (default `http://localhost:8080`). The sync worker therefore never fetches cross-origin, which embedded browsers such as the Claude desktop pane refuse. An absolute URL still works if you want to bypass the proxy.
- Database contract tests (`src/server/db/*.test.ts`) need the local stack running; they skip without it and are required in CI. New migrations: `npx supabase migration up --local`.
- Google Calendar (SYSTEM_DESIGN.md §6): tokens are sealed with `CALENDAR_TOKEN_KEY` (32 bytes base64; `dev-stack.sh` makes one) and Google needs `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET` from a Cloud project with the redirect URI `<NEXT_PUBLIC_APP_URL>/api/calendar/google/callback`; the Settings panel says the calendar is not set up until both exist. The account worker lives in `src/server/calendar/` (no SDK: Google over fetch) and runs from route handlers — the OAuth callback's `after()`, `POST /api/calendar/sync` ("Sync now"), `POST /api/calendar/tick` (pg_cron twice an hour with `PUSH_TICK_SECRET`) and the webhook `POST /api/webhooks/google-calendar` (push channels register only when the app URL is HTTPS and `GOOGLE_WEBHOOK_TOKEN_SECRET` is set). `private.calendar_accounts` is reached only through the `calendar_*` service-role functions; the client sees accounts through `public.calendar_connections`. Writing blocks back (§6.5–§6.6): `push_state` on `time_blocks` is server-owned — a trigger re-queues a synced block that moves, the worker (`src/server/calendar/push.ts`) writes with the block's uuid as the event id and an `extendedProperties` tag, `POST /api/calendar/push` runs it for one person right after a block changes (debounced from `use-block-repo`), the tick and "Sync now" run it too, and inbound copies of our events are ignored, adopted (Google wins, block locked) or detached by `decideEcho`. Scopes (DECISIONS.md, amendment 2026-10-21): connect asks only for the non-sensitive set (`calendarlist.readonly` + `events.freebusy`, no "unverified app" screen) and writing adds `app.created` (blocks go to an app-made "Sparehour" calendar); an account without `events.readonly` is read through `freeBusy.query` as untitled "Busy" rows (`syncCalendarsBusy`), except that Sparehour calendar, read in full. Full access (titles, `events.owned`) is the Settings opt-in, `/api/calendar/google/start?purpose=full`, and brings Google's warning until the app is verified. `calendar_connections.can_read_titles` / `can_write_own` tell the client which an account has. **Outlook / Microsoft 365** (SYSTEM_DESIGN.md §6.8 "As built"; DECISIONS.md, amendment 2026-11-15) is read only and needs `MICROSOFT_OAUTH_CLIENT_ID` / `MICROSOFT_OAUTH_CLIENT_SECRET` from an app registered in the Microsoft Entra admin center (account types "Any Entra ID Tenant + Personal Microsoft accounts", a Web redirect URI `<NEXT_PUBLIC_APP_URL>/api/calendar/microsoft/callback`; DEPLOY.md step 9); without both there is no Outlook at all (no button, `/api/calendar/microsoft/*` is 404) and `/api/calendar/config` answers `{ google, microsoft }`. `src/server/calendar/microsoft.ts` is Graph over fetch (the delta query over each calendar's view; the pages it was written from are in its header): connect asks for `openid email offline_access Calendars.ReadBasic`, the least Microsoft has, and the title Graph sends anyway is never kept (`summary` is null), so never map another field of an Outlook event without a ruling. The worker's ports are handed the account and `run.ts` picks the provider by `provider`; an Outlook calendar's sync token is `YYYY-MM-DD|<deltaLink>` and is re-read in full after 30 days. Nothing is written to Outlook: keep an Outlook calendar out of every write path (`takesBlocks`, `writerFor`, `private.write_calendar_of`), and never send one provider's token to another (Disconnect and account deletion revoke at Google only for a Google account). It has not been run against a real Microsoft account yet.
- Server-owned columns and ownership are enforced in Postgres, not only in the sync route: BEFORE triggers (`private.*_guard`, migration `20260916000100`) restore columns like `tasks.carry_count`, `time_blocks.push_state`, `calendars.calendar_account_id`, `user_settings.space_id` for `authenticated` writers (a few, such as `tasks.auto_filed_at` and `time_blocks.notice`, a person may clear but never set: `CLEARABLE_COLUMNS`), and `calendar_events` is read-only to people. Keep `SERVER_OWNED_COLUMNS` in `src/server/sync/upload.ts` and those triggers in step. Time zones are validated on write; push endpoints must be public HTTPS. `/api/sync/token` refuses the shared local `POWERSYNC_JWT_SECRET` in production unless `ALLOW_DEV_SECRETS=1` (CI and `dev-stack.sh` set it). Before a real deployment: rotate `powersync_role`'s password (`20260914000200_powersync_role.sql`), the PowerSync API token (`powersync/config/powersync.yaml`) and `PS_SYNC_JWT_K`; the design's nonce CSP is not in place yet.
- Finished tasks are kept (DECISIONS.md, amendment 2026-11-14; migration `20261114000100`). The device and the sync streams hold a week of them; the nightly `private.archive_done_tasks()` moves older ones from `tasks` into `public.finished_tasks` (a task's columns plus `checklist`, `tag_ids`, `blocks`, and `occurrence_of` / `occurrence_date` for a repeat's finished day), which is never synced and is read-only for people. A column added to `tasks` must be added to `finished_tasks` too (`src/server/db/finished-tasks.test.ts` fails otherwise). They are read through `GET /api/logbook/older` → `public.finished_tasks_page` (`src/server/logbook/older.ts`), and on the client only through `src/features/finished/` (`fetchFinished`, `useFinished`, the read-only `FinishedPeek`, search's `OlderFound` island): the Logbook's "Show older", search, the export (`features/export/older.ts` unfolds them into rows) and the MCP `search` with `include_done`. Reopen is `data/repositories/finished-restore.ts`: the row is written to the device's `tasks` and uploaded as any new task, and the `tasks_leave_finished` trigger removes the finished row. A cursor's `completed_at` must go back as the string it came as (microseconds), never through a JS `Date`. Deleting one for good (amendment 2026-11-15, migration `20261115000100`): the table stays `SELECT`-only for people, and `public.finished_task_delete(id)` (security definer, one row the caller may read, refuses a read-only app) is the only way in, called by `DELETE /api/logbook/older/[id]` and, on the client, by `FinishedPeek` through `features/finished/finished-delete.ts`; it asks once in place, has no undo, and drops the row from a list only on the server's word. Never add a write grant or a write policy to `finished_tasks` (`src/server/db/finished-task-delete.test.ts` fails if one appears). Today's past day older than the device's week reads its finished tasks through `useFinishedDay` inside `DoneSection` (`features/today/day-states.tsx`), never in the Today shell.
- How long a task took (DECISIONS.md, amendment 2026-11-15): one optional tap under a completion's toast writes `tasks.actual_min` (a repeat's on `task_completions.actual_min`) through `data/repositories/took.ts`; the write is made with `restoreRow` because a finished row leaves the device moments after it uploads, and it records no undo entry of its own. `core/estimates` learns from those by estimate size and only ever suggests ("Tasks like this usually take you 50m." + Use, in quick add, the detail and Settings › Planning); never change an estimate or the capacity engine's inputs from it without the person's tap. `/api/estimates/learned` reads as the user; the device caches the answer (`sparehour.learned`).
- Gaps too short to use (DECISIONS.md, amendment 2026-11-15): an open stretch of the working day under `USABLE_GAP_MIN` (15 minutes, `src/core/capacity`) is not spare time. `spare = work − busy − gaps − buffer − committed − unscheduled`, and the buffer's cap is `work − busy − gaps`. `Capacity.free` still lists those stretches (the timeline draws them, a block can go there by hand), so never take spare time from a sum of `free`, and anything that restates the number (the ribbon's breakdown, `fitsToday`, the push figures, `capacityLine`, `aheadDays`) must subtract `Capacity.gapMin` with the meetings. Plan my day counts what it leaves the same way (`usableAhead` in `core/planning`).
- Lists were taken out of the app on 2026-11-14 (DECISIONS.md, amendment of that date). No screen, quick-add path, search or MCP tool reads or writes them. The data layer stays until the data is deleted: the tables `lists`, `list_items` and `list_item_tags` with `private.lists_guard` and their policies (migration 20261022000100, still tested in `src/server/db/lists.test.ts`), their entries in the `apply_mutations` allow-list, `src/server/sync/upload.ts` and the `space_data` stream, and in `src/data/schema.client.ts` so Settings › Data still exports them (`core/export`). Do not build on them; dropping them is a hosted migration and a stream change, which need the user's OK. `/share` (the manifest's `share_target`, Android) now hands what was shared to quick add as a task (`features/share/shared.ts`); `/lists` and `/list/:id` redirect to Today (`next.config.ts`).
- MCP for Claude (DECISIONS.md, amendment 2026-10-23): `/api/mcp` is the MCP TypeScript SDK v2's `createMcpHandler` (stateless), behind tokens from Supabase Auth's OAuth 2.1 server. `src/server/mcp/auth.ts` takes only app tokens (a `client_id` claim), asks the auth server about each, and reads the access chosen for the app from `public.app_connections`; the tools (`tools.ts`) call the `Planner` (`planner.ts`), which reads through `PlannerStore` (PostgREST as the person; `store.fake.ts` in tests) and writes ops through `apply_mutations` as device `mcp:<client_id>`, reusing the app's own rules (`features/quickadd/file-line.ts`, `core/quickadd/draft-row.ts`, `core/recurrence/completion.ts`). `plan_day` and `apply_day_plan` (amendment 2026-11-14) are Plan my day itself: `core/planning`'s scheduler over an input built as `features/planning/plan-input.ts` builds it, shown first and written as `source = 'plan'` blocks only when asked. Discovery is `/.well-known/oauth-protected-resource/api/mcp` (public in the proxy); consent is `/oauth/consent` and `/oauth/decision`; Settings › Connected apps uses `/api/connections`. A read-only connection is enforced in Postgres by restrictive `<table>_app_insert/_update/_delete` policies on `private.app_may_write()`: a new table people can write needs them too (`src/server/db/app-connections.test.ts` fails otherwise). Fractional sort keys are compared by code unit in JS (`lastKey`), never with a Postgres `order by` (en_US collation). Locally the OAuth server is on in `config.toml` and `site_url` is `http://localhost:3100`, so run the app on 3100 to connect Claude Code.
- Web Push needs `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `PUSH_TICK_SECRET` and `NEXT_PUBLIC_APP_URL` (`dev-stack.sh` writes local ones). The service worker only registers in production builds, so reminders are tested on `npm run build && npm start`, not `npm run dev`.

## Conventions
- Next.js 16 App Router under `src/app`, TypeScript, Tailwind CSS v4, npm. Import alias `@/*` → `src/*`.
- Every record will carry a `space_id` (personal space for now) so team spaces can be added later without a migration.
- Tasks have a do-date, an optional deadline and an optional start date. Only missed deadlines are shown as overdue/red.
- AI features are optional and labeled, and run server-side only — never expose provider keys to the browser.
- Mobile-first, always: every screen must work at 360 px wide and on touch. Write the phone layout first and widen with `min-width` queries; 44 px targets; no hover-only actions; a tap path for every drag. Width bands and per-screen behaviour are in `docs/design/DESIGN_SYSTEM.md` §4a.
- Verify changes with `npm run lint` and `npm run build`. `npm run size` (after a build) checks the gzipped first download of each app shell against its ceiling (320 KB); the quick-add sheet, the task detail (panel and its wiring, `task-detail-connected.tsx`), the palette with its wiring (`palette-host.tsx`) and its own commands (`commands/palette-runs.ts`: every command without a key; the keyboard layer, `command-runs.ts`, keeps only keyed ones), the bulk bar, the notification deep link (`push-actions.tsx`), the first-block reminder ask (`notifications/block-nudge.tsx`), each Settings section (`features/settings/section-islands.tsx`; the page keeps only the section list), the forced-update check (`features/pwa/version-gate.tsx`, mounted by `PwaProvider`), the task detail's surface (`tasks/task-detail-surface.tsx`, which loads the panel) and the context pane's edge (`shell/pane-resizer.tsx`, its look in its own `<style>`), the sync chip's expanded panel (`shell/sync-panel.tsx`), Today's calendar lines (`today/calendar-lines.tsx`, which read `today/calendar-state.ts`), the storage-full banner and the error panel (`ui/error-panel.tsx`, loaded with React `lazy` behind `app/(app)/error.tsx`, `app/global-error.tsx` and `ui/pane-boundary.tsx`) and Settings' export builders (`features/export/build.ts`, which owns fflate) are `next/dynamic` islands prefetched on idle (`features/shell/preload-on-idle.ts`; `useIdleMount` keeps a stateful island mounted once loaded or first needed). The rows' drag adapter (`features/tasks/drag-adapter.ts`: rows wire up once it is in; Today starts it as the page mounts), the redo's capture half (`data/repositories/redo-capture.ts`, loaded by the undo provider) and quick-add's new project (`createProject` in the sheet's own island) stay out of the shells the same way. Turbopack keeps a module whole, unused exports and all, so a shell file importing one helper from a big module carries the whole module: split the module instead. Tailwind reads only the app's sources (`@source not` in `globals.css` leaves out the docs, specs, tests and SQL, whose words it took for class names). The theme's pre-paint script lives in `commands/theme-bootstrap.ts`, which only the root layout imports. Chrono is imported as `chrono-node/en`, and the recurrence helpers are imported from `@/core/quickadd/recurrence` rather than the package index — keep it that way, or the parser lands back in the shell.
- End-to-end: `npm run e2e` (Playwright, `e2e/`) builds and starts the production server on port 3100 against the running local stack and signs in as the dev account; it needs `npm run dev:stack` up. Rows it creates start with "E2E " and are removed afterwards. `npm run e2e:ui` for the inspector; set `E2E_SKIP_BUILD=1` to reuse an existing build. The sign-in setup also switches the dev account's morning review off (`user_settings.carry_review = false`), because that account always has carried-over tasks and the review sheet would otherwise open on every first visit; `e2e/carry-review.spec.ts` turns it on for itself. A new account meets the first run (`/welcome`, gated on `user_settings.onboarded_at`; its calendar step shows only where `/api/calendar/config` says a calendar can be connected, Google or Outlook, which the local stack cannot; `e2e/calendar-outlook.spec.ts` and `first-run-phone.spec.ts` stub that answer) before anything else: the seed and the sign-in setup mark the dev account done, a spec that makes its own account stamps it (or walks through it, as `magic-link.spec.ts` does).
