# Sparehour

A calm, time-aware personal planner (product formerly worked on as "Personal Work Management"). Core promise: a Today that knows your real free time, and a guilt-free planning loop.

## Before building anything
- Read `docs/DECISIONS.md`. It is the source of truth for product decisions and lists the open ones — don't silently decide an open question in code; ask.
- Check a feature's milestone tag in `docs/FEATURES.md`. Build only what the current milestone needs; park the rest.
- Data/sync layer: **PowerSync + Supabase**, confirmed by the P0 spike (`docs/engineering/SYSTEM_DESIGN.md` Appendix A′, 2026-09-14; A4 iOS PWA storage still pending a real iPhone). Local stack: `npm run dev:stack` (Supabase on 54321/54322, PowerSync on 8080, writes `.env.local`), then `npm run dev`; sign in as `dev@sparehour.local` / `sparehour`. `@powersync/*` is imported only under `src/data/powersync/` (ESLint enforces it); `src/core/**` stays free of React, data and server imports.
- Sync streams can only match subscription parameters with `=` / `IN` — windowed streams are keyed by month (`months: ['2026-09', …]`), never by a date range.
- Sign-in (DECISIONS.md Q25): an emailed six-digit code or link (`signInWithOtp`; the local template `supabase/templates/magic_link.html` carries both, Mailpit at http://127.0.0.1:54324 catches it) and Google, identity only. `/auth/callback` exchanges a PKCE code or verifies a token hash and sets the cookie. The Google button appears only when the auth server reports the provider enabled: create a Web OAuth client with redirect URI `http://127.0.0.1:54321/auth/v1/callback`, export `SUPABASE_AUTH_EXTERNAL_GOOGLE_CLIENT_ID` / `_SECRET`, set `enabled = true` under `[auth.external.google]` in `supabase/config.toml`, restart the stack. The password form stays for the dev account and the e2e suite.
- Sync auth: the browser never shows PowerSync its Supabase session. `GET /api/sync/token` mints a five-minute HS256 token with `POWERSYNC_JWT_SECRET`; the service verifies it with the same secret (`PS_SYNC_JWT_K`, base64url, defaulted to the local dev value in `powersync/docker-compose.yml`). `dev-stack.sh` writes the local secret into `.env.local`.
- The browser reaches PowerSync through its own origin: `NEXT_PUBLIC_POWERSYNC_URL=/powersync` and a rewrite in `next.config.ts` to `POWERSYNC_INTERNAL_URL` (default `http://localhost:8080`). The sync worker therefore never fetches cross-origin, which embedded browsers such as the Claude desktop pane refuse. An absolute URL still works if you want to bypass the proxy.
- Database contract tests (`src/server/db/*.test.ts`) need the local stack running; they skip without it and are required in CI. New migrations: `npx supabase migration up --local`.
- Google Calendar (SYSTEM_DESIGN.md §6): tokens are sealed with `CALENDAR_TOKEN_KEY` (32 bytes base64; `dev-stack.sh` makes one) and Google needs `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET` from a Cloud project with the redirect URI `<NEXT_PUBLIC_APP_URL>/api/calendar/google/callback`; the Settings panel says the calendar is not set up until both exist. The account worker lives in `src/server/calendar/` (no SDK: Google over fetch) and runs from route handlers — the OAuth callback's `after()`, `POST /api/calendar/sync` ("Sync now"), `POST /api/calendar/tick` (pg_cron twice an hour with `PUSH_TICK_SECRET`) and the webhook `POST /api/webhooks/google-calendar` (push channels register only when the app URL is HTTPS and `GOOGLE_WEBHOOK_TOKEN_SECRET` is set). `private.calendar_accounts` is reached only through the `calendar_*` service-role functions; the client sees accounts through `public.calendar_connections`. Writing blocks back (§6.5–§6.6): `push_state` on `time_blocks` is server-owned — a trigger re-queues a synced block that moves, the worker (`src/server/calendar/push.ts`) writes with the block's uuid as the event id and an `extendedProperties` tag, `POST /api/calendar/push` runs it for one person right after a block changes (debounced from `use-block-repo`), the tick and "Sync now" run it too, and inbound copies of our events are ignored, adopted (Google wins, block locked) or detached by `decideEcho`.
- Server-owned columns and ownership are enforced in Postgres, not only in the sync route: BEFORE triggers (`private.*_guard`, migration `20260916000100`) restore columns like `tasks.carry_count`, `time_blocks.push_state`, `calendars.calendar_account_id`, `user_settings.space_id` for `authenticated` writers, and `calendar_events` is read-only to people. Keep `SERVER_OWNED_COLUMNS` in `src/server/sync/upload.ts` and those triggers in step. Time zones are validated on write; push endpoints must be public HTTPS. `/api/sync/token` refuses the shared local `POWERSYNC_JWT_SECRET` in production unless `ALLOW_DEV_SECRETS=1` (CI and `dev-stack.sh` set it). Before a real deployment: rotate `powersync_role`'s password (`20260914000200_powersync_role.sql`), the PowerSync API token (`powersync/config/powersync.yaml`) and `PS_SYNC_JWT_K`; the design's nonce CSP is not in place yet.
- Web Push needs `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `PUSH_TICK_SECRET` and `NEXT_PUBLIC_APP_URL` (`dev-stack.sh` writes local ones). The service worker only registers in production builds, so reminders are tested on `npm run build && npm start`, not `npm run dev`.

## Conventions
- Next.js 16 App Router under `src/app`, TypeScript, Tailwind CSS v4, npm. Import alias `@/*` → `src/*`.
- Every record will carry a `space_id` (personal space for now) so team spaces can be added later without a migration.
- Tasks have a do-date, an optional deadline and an optional start date. Only missed deadlines are shown as overdue/red.
- AI features are optional and labeled, and run server-side only — never expose provider keys to the browser.
- Mobile-first, always: every screen must work at 360 px wide and on touch. Write the phone layout first and widen with `min-width` queries; 44 px targets; no hover-only actions; a tap path for every drag. Width bands and per-screen behaviour are in `docs/design/DESIGN_SYSTEM.md` §4a.
- Verify changes with `npm run lint` and `npm run build`. `npm run size` (after a build) checks the gzipped first download of each app shell against its ceiling (320 KB); the quick-add sheet, the task detail (panel and its wiring, `task-detail-connected.tsx`), the palette with its wiring (`palette-host.tsx`), the bulk bar, the notification deep link (`push-actions.tsx`), the first-block reminder ask (`notifications/block-nudge.tsx`), each Settings section (`features/settings/section-islands.tsx`; the page keeps only the section list) and Settings' export builders (`features/export/build.ts`, which owns fflate) are `next/dynamic` islands prefetched on idle (`features/shell/preload-on-idle.ts`; `useIdleMount` keeps a stateful island mounted once loaded or first needed). Turbopack keeps a module whole, unused exports and all, so a shell file importing one helper from a big module carries the whole module: split the module instead. Chrono is imported as `chrono-node/en`, and the recurrence helpers are imported from `@/core/quickadd/recurrence` rather than the package index — keep it that way, or the parser lands back in the shell.
- End-to-end: `npm run e2e` (Playwright, `e2e/`) builds and starts the production server on port 3100 against the running local stack and signs in as the dev account; it needs `npm run dev:stack` up. Rows it creates start with "E2E " and are removed afterwards. `npm run e2e:ui` for the inspector; set `E2E_SKIP_BUILD=1` to reuse an existing build. The sign-in setup also switches the dev account's morning review off (`user_settings.carry_review = false`), because that account always has carried-over tasks and the review sheet would otherwise open on every first visit; `e2e/carry-review.spec.ts` turns it on for itself.
